Demo scenarios

What the audience should take away

1. It finds AI on its own
From code, keys, computers, agents, internet traffic and data movement
2. It links the clues
Clues that share a repo, key, user + website or server become one case
3. It tells good from risky
Approved use stays quiet. Shadow and risky use is raised
4. It explains every decision
Evidence, points per factor and the rule that fired

How clues are linked (join rules)

RuleLinks two clues when…Used in
J1Same repo/app name and same AI providerS1, S2
J2Same credential fingerprint(key reuse)
J3Repo's service account/author = proxy user and same providerS2, S7
J4Network + DLP: same user, same website, within ±2 minutesS3, S7
J5Same device and same AI runtime (process ↔ port ↔ model file)S4
J6MCP config server ↔ running server ↔ tool-call auditS5
Over-merge guard: the same user, device or provider alone never links clues. That is why Ahmed's local model (S4), agent (S5) and Anthropic use (S7) stay three separate cases.

Decision rules (first match wins)

R1 · confidence < 40 → FALSE POSITIVE
R2 · Approved AND confidence ≥ 70 → GENUINE
R3 · not Approved AND risk ≥ 70 → RAISE ISSUE
R4 · otherwise → MONITOR
