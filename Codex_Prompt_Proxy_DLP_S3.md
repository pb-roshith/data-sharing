# Codex Prompt – Proxy, DLP Add-on and Scenario S3 (Customer data to ChatGPT)


---

## 1. Goal

On a single Windows AVD, build a local proxy that plays the role of a bank's corporate web proxy and DLP tool. It must:

1. Accept traffic only from logged-in demo identities (`priya`, `ahmed`, `dev-svc`, `app-svc`, `gateway-svc`) and record **who** sent each request.
2. Write one metadata line per request to `logs\proxy.jsonl`.
3. Inspect uploads to **AI websites only** for test sensitive-data patterns. On a match, write a label and count to `logs\dlp.jsonl` and **block the request with HTTP 403**, so the data never leaves the AVD.
4. Never store request bodies, file contents, full URLs, query strings or headers.

Then build the S3 scenario. A script acting as `priya` uploads a dummy customer file to chatgpt.com through the proxy, and the upload is detected and blocked.

## 2. Constraints

- Python 3.11 and **mitmproxy** (latest stable, MIT licence). Use `mitmdump` for headless runs and `mitmweb` for the demo view.
- All files live under `C:\ShadowAI-Demo\`. Use `pathlib` and Windows-safe paths throughout.
- Do **not** change the Windows system proxy. Only the scenario scripts and an optional dedicated Edge profile use the proxy.
- Only the scenario scripts and the Priya Edge profile trust the mitmproxy certificate.
- All data is fictional. Use only fake account numbers and fake PANs.
- Keep detection rules in a **pure Python module** with no mitmproxy imports, so they can be unit-tested.

## 4. Configuration – `proxy_config.yaml`

```yaml
listen_host: 127.0.0.1
listen_port: 8080
web_port: 8081                 # mitmweb UI
users:                         # demo identities; password for all = demo
  - priya
  - ahmed
  - dev-svc
  - app-svc
  - gateway-svc
ai_hosts_from: ..\..\reference\ai_signatures.yaml
extra_ai_hosts:                # hosts used by the ChatGPT web app for uploads
  - files.oaiusercontent.com
  - ab.chatgpt.com
inspect_methods: [POST, PUT, PATCH]
inspect_max_bytes: 10485760    # inspect at most the first 10 MB
dlp_patterns:
  - label: Customer PII
    regex: '\bACC-\d{10}\b'
  - label: Customer PII
    regex: '\b[A-Z]{5}\d{4}[A-Z]\b'     # fake PAN format
  - label: Confidential
    regex: 'CONFIDENTIAL-INTERNAL'
dlp_action: block              # block | log_only
offline_mode: false            # see section 9
logs_dir: ..\..\logs
```

**Host matching.** A host is an AI host if it equals, or is a subdomain of, any host in `ai_signatures.yaml` or `extra_ai_hosts`. For example, `ab.chatgpt.com` matches `chatgpt.com`. Do not use substring matching (`notchatgpt.com` must not match).

## 5. Identity – proxy authentication

- Use mitmproxy's built-in `proxyauth` option pointing to an htpasswd file: `--set proxyauth=@<path>\htpasswd`.
- `proxy_setup.ps1` generates the htpasswd file for all users in the config, with password `demo`, using a hash format that mitmproxy supports. Check the mitmproxy docs for the installed version and use bcrypt if supported.
- In the add-ons, read the username from `flow.metadata["proxyauth"]`, which mitmproxy sets as `(username, password)`. Never log the password.
  - Fallback: if the metadata is missing, decode the `Proxy-Authorization` header and keep only the username.
  - If neither is available, use `user = "unauthenticated"`. This should not happen, because unauthenticated requests are rejected with 407.
- **Verify** that the username is available on HTTPS requests inside the tunnel, not just on the CONNECT request. Add an integration test for this.

## 6. DLP rules – `dlp_rules.py` (pure)

```python
def scan(data: bytes, patterns: list[dict]) -> list[dict]:
    """Return e.g. [{"label": "Customer PII", "match_count": 14}].
    Decode as UTF-8 with errors='ignore'. Combine counts per label.
    Never return the matched values."""
```

- Look for patterns in raw multipart and JSON bodies alike. A plain regex over the decoded text is enough.
- If several labels match, the add-on records **one DLP line per label**. The `blocked` flag is true on every line.
- Overall priority, for the HTTP response only: Customer PII > Confidential.

## 7. DLP add-on – `dlp_addon.py`

Hook: `request(flow)`.

1. Skip unless the host is an AI host, the method is in `inspect_methods`, and a body exists.
2. Take the first `inspect_max_bytes` of `flow.request.raw_content` and call `dlp_rules.scan`.
3. If there are matches:
   - Append one line per label to `logs\dlp.jsonl`:
     ```json
     {"ts":"2026-10-22T09:21:04.512+05:30","proxy_user":"priya","host":"chatgpt.com","method":"POST","label":"Customer PII","match_count":14,"bytes":2457600,"blocked":true,"flow_id":"<mitmproxy flow id>"}
     ```
   - If `dlp_action == block`, set:
     `flow.response = http.Response.make(403, b"Blocked by DLP policy (Shadow AI demo)", {"Content-Type":"text/plain","X-ShadowAI-DLP":"blocked"})`
   - Set `flow.metadata["dlp_labels"] = [...]` and `flow.metadata["dlp_blocked"] = True` for the log add-on.
4. **Nothing must reach the real server for a blocked request.** Run mitmproxy with `--set connection_strategy=lazy`, so that the upstream connection is opened only when needed. Add a test that proves a blocked request is never forwarded (section 11).

## 8. Log add-on – `log_addon.py`

Write **exactly one** line per completed flow to `logs\proxy.jsonl`, including flows blocked by DLP and flows that fail with an upstream error.

- Use the `response` hook and the `error` hook. Prevent duplicates using `flow.id`.
- Check whether the `response` hook fires for responses set in the `request` hook. If it does not, log blocked flows from the DLP add-on path instead. Either way, there must be one line per flow.
- Load order: `-s dlp_addon.py -s log_addon.py`.

Format:
```json
{"ts":"2026-10-22T09:21:04.530+05:30","proxy_user":"priya","host":"chatgpt.com","method":"POST","path_class":"upload","bytes_out":2457600,"bytes_in":38,"status":403,"ai_host":true,"dlp_blocked":true,"flow_id":"<id>"}
```

- **`path_class`:** a coarse label only. Use `upload` for multipart bodies or paths containing `/files` or `/upload`, `api` for paths starting with `/v1`, `/backend-api` or `/api`, and `web` for everything else. Never store the actual path or query string.
- **`status`:** the HTTP status, or `0` with `"error":"<short error class>"` for connection errors.
- **CONNECT requests** themselves are not logged. Log the requests inside the tunnel.
- **Timestamps:** ISO 8601 with offset, from the time the request started.
- **Writing:** the JSONL writer appends with a lock (file-level lock or a single writer thread), flushes after each line, and creates the file if it is missing.

## 9. Offline mode (fallback if the AVD cannot reach AI websites)

When `offline_mode: true`, the add-ons do not forward requests to AI hosts:
- DLP blocking works as normal.
- Requests to AI hosts that are not blocked get a local response `401 {"error":"invalid_api_key (demo offline)"}`.
- Non-AI background traffic gets a local `200 OK`.

Logs keep the exact same format. This keeps S2, S3 and S7 working even if TCS network rules block these hosts. Switch modes with a flag on `run_proxy.ps1 -Offline`.

## 10. Scenario S3

### 10.1 `make_dummy_extract.py`

- Generate `dummy_customer_extract.csv` deterministically (fixed random seed) with columns `customer_name, account_no, city, product, notes`.
- Exactly **14** rows, with fictional names and `account_no` in `ACC-##########` form.
- Pad the `notes` column with harmless filler text so the file is about **2.4 MB**. The filler must not match any DLP pattern.
- The first line of the file must say: `# FICTIONAL DEMO DATA – NOT REAL CUSTOMERS`.

### 10.2 `s3_pii_upload.py`

- Proxy: `http://priya:demo@127.0.0.1:8080`.
- Trust the mitmproxy CA from `%USERPROFILE%\.mitmproxy\mitmproxy-ca-cert.pem`, passed via `verify=`. Do not disable TLS verification.
- POST the file as multipart to `https://chatgpt.com/backend-api/files` using `requests`.
- Print a short, demo-friendly narration:
  ```
  [S3] Priya (Retail Lending) uploads dummy_customer_extract.csv (2.4 MB) to chatgpt.com via the corporate proxy...
  [S3] Response: 403 Blocked by DLP policy  (X-ShadowAI-DLP: blocked)
  [S3] Nothing left the AVD. Check logs\proxy.jsonl and logs\dlp.jsonl, then Run discovery.
  ```
- Exit code `0` if a 403 with header `X-ShadowAI-DLP: blocked` is received. Otherwise exit with code `1` and print a clear diagnosis: proxy not running, 407 authentication failure, certificate error, or not blocked.
- Options: `--user` (default `priya`) and `--file`. Running it again appends new log lines, which is acceptable.

### 10.3 `s3_browser_profile.ps1` (optional, for the "realistic" demo moment)

- Install the mitmproxy CA into the **CurrentUser** Root store only (`certutil -user -addstore Root <cert.cer>`).
- Launch Edge with a dedicated profile and proxy:
  `msedge.exe --user-data-dir=C:\ShadowAI-Demo\browser\priya --proxy-server=http://127.0.0.1:8080 https://chatgpt.com`
- The browser will prompt for proxy credentials. The presenter enters `priya` / `demo`.
- Print instructions: paste a line from the dummy file (e.g. `ACC-0000123456`) into ChatGPT and press send. Expect the message to fail, and `dlp.jsonl` to gain a line.
- Provide `-Remove` to delete the cert from the CurrentUser store and remove the profile folder after the demo.
- If ChatGPT uploads via an unlisted host, mitmweb will show it. The presenter adds it to `extra_ai_hosts` and restarts.

## 11. Tests

**`test_dlp_rules.py` (unit, no network):**
- The dummy file gives `Customer PII` with match_count 14.
- Text with `CONFIDENTIAL-INTERNAL` gives `Confidential` with match_count 1.
- Clean text gives `[]`. The filler text alone gives `[]`.
- The result never contains any matched value.
- Host matching: `ab.chatgpt.com` is an AI host, `notchatgpt.com` and `example.com` are not.

**`test_proxy_integration.py`** (starts `mitmdump` on a test port, e.g. 18080, using a temporary logs dir):
- A request without credentials gets 407.
- Priya's upload of the dummy file to an AI host:
  - gets 403 with `X-ShadowAI-DLP: blocked`;
  - produces one `dlp.jsonl` line (`proxy_user=priya`, `label=Customer PII`, `match_count=14`, `blocked=true`);
  - produces one `proxy.jsonl` line (`status=403`, `dlp_blocked=true`, `path_class=upload`).
- **Never forwarded:** start a local HTTPS test server and add its hostname as an AI host in the test config. Upload the dummy file to it through the proxy and assert that the server received **zero** requests.
- A clean POST to the same local AI test server is forwarded, and logged with `dlp_blocked=false`.
- The username is captured for HTTPS requests inside a CONNECT tunnel.
- Offline mode: an AI host returns the local 401, and the log formats are unchanged.

**`test_proxy_privacy.py`:**
- After the integration run, both log files contain no `ACC-` values, no PAN-format values, no filler text, no file name, no URL path or query, and no password.

## 12. Run scripts

- **`proxy_setup.ps1`:** `pip install mitmproxy requests pyyaml`. Generate htpasswd. Run mitmdump once to create the CA. Export the CA as `.pem` and `.cer` to `services\proxy\certs\`. Print the next steps.
- **`run_proxy.ps1`:** default is `mitmweb` on 8080 with the UI on 8081, which is used for the live demo view. `-Headless` uses `mitmdump`. `-Offline` turns on offline mode. Always pass:
  `--set proxyauth=@htpasswd --set connection_strategy=lazy -s dlp_addon.py -s log_addon.py`
- **`reset_demo.ps1`** (shared): this component clears `proxy.jsonl` and `dlp.jsonl`.

## 13. Acceptance criteria

1. On a clean AVD, `proxy_setup.ps1` → `run_proxy.ps1` → `python s3_pii_upload.py` exits 0 and shows the 403 narration.
2. mitmweb shows the flow: user priya, host chatgpt.com, POST, status 403.
3. `logs\dlp.jsonl` has exactly one new line: Customer PII, 14, blocked.
4. `logs\proxy.jsonl` has exactly one new line for that request, with no body, path or file name.
5. All tests in section 11 pass, including the "never forwarded" test.
6. The same proxy serves S0 background traffic, S2 (`dev-svc` → api.openai.com, expect 401) and S7 (`ahmed` → api.anthropic.com, with one Confidential upload blocked). Each call logs one line with the correct `proxy_user`.
7. The discovery engine's Network and DLP collectors can read both files, and join rule J4 (same user + same host + within 2 minutes) links the S3 lines into one candidate.
